# Fresh Boot

Clean-slate procedure: wipe the DB + uSync state, let the schema pipeline
re-create everything from scratch.

Useful when:
- You changed an initializer and want to verify it runs correctly on a fresh DB.
- You want to rebase on the `SeedConfig` defaults (or a new deployment override).
- Stale schema/content state has you debugging phantom issues.

## What gets wiped

| Path | What | Regenerated by |
|---|---|---|
| `Synergos.CMS/umbraco/Data/Synergos.sqlite.db` | SQLite DB (schema + content + users) | Umbraco on first boot + schema pipeline |
| `Synergos.CMS/umbraco/Data/Synergos.sqlite.db-shm` | SQLite shared memory | SQLite |
| `Synergos.CMS/umbraco/Data/Synergos.sqlite.db-wal` | SQLite write-ahead log | SQLite |
| `Synergos.CMS/umbraco/Data/TEMP/` | NuCache runtime caches | Umbraco |
| `Synergos.CMS/umbraco/Logs/` | Serilog rotating logs | Serilog |
| `Synergos.CMS/umbraco/mediacache/` | Processed media thumbnails | ImageSharp on-demand |
| `Synergos.CMS/uSync/v9/` | uSync exports (671 configs) | Manual export from backoffice |
| `Synergos.CMS/bin/Debug/` + `obj/Debug/` | .NET build artifacts | `dotnet build` |

Editor content, users, and passwords live in the DB. **Wiping the DB deletes
them.** Only wipe in dev / CI or when you explicitly want a clean start.

## Procedure

1. **Stop all web hosts.** Close IIS Express tray icon, stop `dotnet run`,
   stop VS's "Run" window. Verify no process holds the DLL:

   ```bash
   # Should return nothing
   lsof Synergos.CMS/bin/Debug/net8.0/Synergos.CMS.dll    # mac/linux
   handle.exe Synergos.CMS.dll                              # windows (sysinternals)
   ```

2. **Delete the DB files.**

   ```bash
   cd Synergos.CMS
   rm -f umbraco/Data/Synergos.sqlite.db umbraco/Data/Synergos.sqlite.db-shm umbraco/Data/Synergos.sqlite.db-wal
   rm -rf umbraco/Data/TEMP  # optional — NuCache refreshes on boot
   ```

3. **Delete the uSync cache.** uSync configs reflect the old schema and would
   import stale state if `ImportOnStartup: true` (it's false by default, but
   clear anyway for peace of mind).

   ```bash
   rm -rf uSync/v9
   ```

4. **Clean the build output.** Ensures no stale DLLs are loaded.

   ```bash
   rm -rf bin/Debug obj/Debug
   ```

5. **Rebuild.**

   ```bash
   cd ..
   dotnet build Synergos.CMS/Synergos.CMS.csproj
   ```

   Expected: `0 Errores`, 1 Advertencia (NU1902 Umbraco advisory).

6. **Run.**

   ```bash
   cd Synergos.CMS
   dotnet run --launch-profile "Umbraco.Web.UI"
   ```

7. **Watch the logs.** You should see (abridged):

   ```
   [INF] Synergos schema mismatch (stored=none, expected=10.0.1). Running pipeline.
   [INF] [Phase 0] Cultures — ensured 1 language
   [INF] [Phase 1a] DataTypes — created 45 data types
   …
   [INF] [Phase 7] Element Types — created 58 element types
   [INF] [Phase 9a] Document Types + ShopInitializer
   [INF] [Phase 9b] PlatformInitializer + SiteSettingsInitializer
   …
   [INF] Synergos schema complete (10.0.1).
   [INF] ContentSeeder: verifying content tree...
   [INF] ContentSeeder: created PlatformRoot (id=1234).
   [INF] ContentSeeder: created GlobalSettings, SharedContent under PlatformRoot.
   [INF] ContentSeeder: created SiteRoot 'Synergos'.
   [INF] ContentSeeder: created pages Home, Nosotros, Servicios, Contacto.
   [INF] ContentSeeder: seed complete.
   [INF] Content is ready and running!
   ```

8. **Create the admin user.** Browse to `https://synergos.local:5001/umbraco`
   (or `http://localhost:4046/umbraco` for IIS Express). Umbraco's unattended
   install wizard prompts for a user on first run.

9. **Verify the content tree.** In the backoffice:
   - `Platform` tree → Synergos Platform → Global Settings (2 tabs), Shared Content, Synergos (siteRoot).
   - Under Synergos: Site Settings (10 tabs, no Blog tab, no CDN tab), Theme Settings (7 tabs), Home, Nosotros, Servicios, Contacto.
   - `Settings` → Document Types → confirm the structure matches CLAUDE.md §4 and docs/schema/content-model.md.

10. **Export uSync.** Go to `Settings → uSync` in the backoffice, click Export.
    This regenerates `uSync/v9/` reflecting the clean schema. **Commit the
    configs** so the CI / deployment can use them as a backup/baseline if
    needed.

## When fresh boot is NOT needed

If you only added properties to an existing type, you don't need to wipe the
DB — just bump `SchemaVersion` and the pipeline re-runs. `TryPatchExistingContentType`
and `EnsureMissingProperties` handle the incremental updates.

Wipe the DB only when:
- The schema changed destructively (property removed, tab renamed destructively).
- You're testing `ContentSeeder` changes and don't want to reset each field manually.
- You're debugging corrupt state from a partial initializer run.

## CI / deployment note

Production deploys **never** wipe the DB. They rely on idempotent initializers
and non-destructive patching. Schema version bumps cause pipeline re-runs that
patch existing types; they don't start fresh.

Test your initializer changes against both:
1. Fresh DB (this procedure).
2. Already-populated DB (upgrade path).

If either path breaks, the initializer is wrong.
